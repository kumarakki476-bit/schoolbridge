# Contributing to SchoolBridge

## Product phase

Do not begin production implementation of a feature until its screen flow, business rules, and acceptance criteria are approved.

## Branching (once coding begins)

- Stable baseline: `main`
- Integrated development: `develop`
- Feature work: `feature/<feature-name>`

## Pull requests

A pull request should state:

1. What changed
2. Why it changed
3. Screens / requirements affected
4. Testing performed
5. Known limitations

## Decisions

Significant product or technical decisions must be added to `docs/decision-log.md`.

## Security

Never commit credentials, API keys, passwords, tokens, real student data, or production secrets to GitHub.
